# Chapter 001: The Repository Appears

```text
FILE: INC-001
STATUS: UNVERIFIED
FIRST SEEN: 03:17 UTC
SOURCE: public repository mirror
READER WARNING: this record has not been stabilized
```

At 03:17 UTC, a repository appeared on GitHub.

A repository was just a public project folder. A place where files lived. A place that remembered who changed what, and when. To most people, it was boring infrastructure. To developers, it was memory.

This repository had no announcement.

No launch post. No linked website. No social account claiming ownership. No one saying, we made this.

That alone was not strange.

The internet produced abandoned things every minute. Half-finished tools. Empty frameworks. Manifestos opened with enormous confidence and forgotten three days later. Projects named like revolutions and maintained like grocery lists.

This one was different for one reason.

It should not have existed.

The repository was called:

```text
black-envelope-protocol
```

It contained one file.

```text
README.md
```

A README is the front door of most projects. Someone leaves a note there: what this is, how to read it, where to begin.

This README had left a note too.

But it did not explain a project.

It sounded as if it had noticed being read.

For the first seventeen minutes, nobody noticed the repository.

At 03:34 UTC, a user with the handle `cipherless` opened it.

They had not searched for novels.

They had not searched for mysteries.

They had searched for an ordinary error message.

It was the kind of tired little task people do at night: copy the message from the screen, paste it into a search box, and hope someone else has already hit the same wall.

The result list should have been predictable. Old forum replies. Documentation pages. Forgotten discussions where someone almost answered the question.

Instead, between two ordinary results, there was a repository with a black square as its preview image.

Its description read:

```text
A public archive of a leaking timeline.
```

`cipherless` clicked because it looked like spam.

That was the first mistake.

The README opened instantly.

There was no banner. No image. No attempt to sell a concept. Just plain text.

```text
This is not a novel.

This is a public archive of a leaking timeline.

If you are reading this repository, you are not outside the story.

You are looking at one of its branches.
```

A branch was a side path. In software, people used branches to test another version of a project before returning to the main path.

But in that sentence, branch did not feel like software.

It felt like the wrong door in fate.

Below the text was a timestamp.

```text
first_known_timestamp: 03:17 UTC
```

Below the timestamp was a file path.

```text
incidents/incident-001/canon.md
```

The README was pointing to another file.

But the file did not exist.

`cipherless` reloaded the page.

The path remained.

Still no folder.

Still no file.

It was like finding an address for a street that had not been built yet.

Then they checked the change history.

On GitHub, every saved change leaves a record. That record is called a commit. It is a tiny entry in the project’s memory: what changed, when, and with what note.

This repository had one commit.

Message:

```text
initial threshold detected
```

Author: unavailable.

Date: 03:17 UTC.

The author field was not private. It was not deleted. It did not look broken.

It was worse.

It looked blank in a way blank fields were not supposed to be blank.

`cipherless` took a screenshot.

The screenshot showed the commit.

When they looked back at the page, the commit message had changed.

```text
initial threshold detected / do not stabilize yet
```

There was still one commit.

No new record. No update notice. No sign that anyone had edited the page.

Only the words had changed.

For a while, `cipherless` did the sensible thing.

Nothing.

They stood from the desk, walked to the kitchen, poured the coffee out, rinsed the cup, and waited for the ordinary world to correct itself.

Browsers glitched. Pages loaded badly. Extensions interfered. Lack of sleep made people dramatic.

When they returned, the repository had two files.

```text
README.md
incidents/incident-001/canon.md
```

No new commit.

The second file had appeared inside the first record as if it had always been there.

`cipherless` opened it.

The file was short.

```text
# INC-001: The Repository Appears

reader_status: unstable
first_seen: 03:17 UTC

A public repository appears.

Its first reader assumes it is spam.

The first reader checks the change history.

The commit message changes while being observed.

The first reader takes a screenshot.

The screenshot will not match the page.
```

The final line was not there at first.

It appeared while they were reading.

`cipherless` did not take another screenshot.

Instead, they opened a new tab and searched the repository name.

No results.

They searched the README text.

No results.

They searched the commit message.

No results.

Then they did what almost everyone does when the impossible is small enough to fit inside a screen.

They tried to share it.

The first message went to a private channel with twelve people in it.

```text
anyone else seeing this weird repo?
```

The link preview failed.

The second message included only the repository name.

The third message included a screenshot.

For eight seconds, nobody replied.

Then someone called it an internet game.

Someone else asked who owned it.

A third person reacted with a black square emoji.

By 03:49 UTC, four people had opened the repository.

By 03:52 UTC, seven people had opened it.

By 03:55 UTC, the discussion tab appeared.

On GitHub, it was called an issue. People used issues to ask questions, report problems, or argue with a project.

There was one issue.

No one had opened it.

The title was:

```text
Issue #001: Who wrote this before it was read?
```

`cipherless` stared at the issue number for longer than the words deserved.

Then the README changed again.

A new line appeared below the branch warning.

```text
Do not ask who wrote the archive.

Ask what noticed you reading it.
```

That was when the first reader closed the laptop.

That was also when the repository received its first star.

The account that starred it no longer exists.
